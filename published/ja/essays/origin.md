# Origin — 小さなツールが意味を照らすとき

## 1. 私を支えた 2 つのファイル

私は20年以上、2D CAD と Excel のあいだで仕事をしてきました。

そのなかで、不思議なほど長く使い続けている 2 つのファイルがあります。

- 非常に単純な Excel シート
    
- AutoCAD 図面（ブロックライブラリ）
    

同じフォルダに置かれた、この 2 つのファイルの組み合わせです。

このツールのおかげで私は膨大な図面作業を破綻なくこなし、  
過労で倒れずにすんだと言っても大袈裟ではありません。

その話を少し書いてみます。

---

## 2. 身体で覚えた操作から、コマンドへ

入社当時、3D CAD は一般的ではなく、  
職場は MicroCADAM という 2D CAD を使っていました。

数年かけてようやくアイコンの位置や、  
特殊な CAD 専用キーボードに慣れた頃、  
ベンダー側の事情で AutoCAD へ移行することになりました。

操作体系はまったく別物で、  
それまで積み上げてきた感覚的なスキルは崩れました。

そのため、AutoCAD は GUI ツールでありながら、  
私は「操作はコマンドで指示し、対象選択はマウスで行う」という、
独特の分担で AutoCAD を使うようになりました。

コマンドの指示はショートエイリアスを多用し、  
操作を小さな宣言文として扱うような感覚です。
その“宣言”と最も相性がいいのが、実はコマンドラインでした。

自然と、AutoCAD 最古で最も安定した API＝コマンドラインに  
乗ることになりました。

---

## 3. Excel から CAD へ：最小の接続

当時（20年前）は個人ブログ文化が盛んで、  
CAD オペレータが自身の tips を公開していました。

その中で見かけたのが、次のような “Hello World” です。

Excel に以下の文字列を並べ、  
AutoCAD のコマンドラインに貼り付けます。

```
_xl
h
0,5
0,-5
```

すると、CAD 上には二本の水平線が引かれます。

- 1本目：座標 (0,5)
    
- 2本目：座標 (0,-5)
    

ただそれだけですが、  
「Excel が CAD を動かしている」という感覚が  
自分の中ではっきりとした手応えを持ち始めました。

---

## 4. 部品配置という次のステップ

線が描けるなら、部品も置けるのではないか。

自然と発想はそちらへ向かいます。

AutoCAD は図面内にブロックの定義さえあれば、  
名前と座標に従って挿入してくれます。

プログラムにおける #include にも少し似ています。

試作したのは、次のようなコマンド列でした。

```
-insert
block_A
10,20
1
1
0
```

名前と座標だけで、部品（ブロック）は狙った場所に配置されます。

ここから、私は会社の製品体系に合わせて  
Excel の表を作り始めました。

---

## 5. 製品体系に薄い層をのせる

運が良いことに、会社の製品アーキテクチャは  
次のようにモジュール化されていました。

- 1 ブロック＝1 部品
    
- 図番体系が部品単位で整然と管理されている
    
- 組み合わせで多品種に対応できる
    

私が Excel でやったのは、  
その上にごく薄い層をかぶせることだけです。

Excel ファイルの構成は変わらずシンプルです。

- 1枚目：仕様を選ぶ UI
    
- 2枚目以降：図番・部品名・座標の一覧
    
- 範囲に名前をつけて UI と連動
    
- 最終列に AutoCAD コマンド列を生成する式を書く
    

操作は単純です。

- UI で仕様を選ぶ
    
- 生成された文字列をコピー
    
- AutoCAD のコマンドラインに貼り付ける
    

VBA も、マクロもありません。

Excel が AutoCAD コマンド文字列を作り、  
私はそれを貼るだけです。

もちろん、これだけで図面は完成しません。  
大量の類似オーダーの“背骨”をこのツールが受け持ち、  
固有設計は私が受け持つ、という役割分担でした。

それでもこの仕組みは、15年以上壊れずに残り続けました。

---

## 6. 意味は境界で姿を現す

この単純なツールを使い続けるうちに、気づいたことがあります。

仕様（Excel）を選択し、  
生成された文字列をコピーし、  
図面（AutoCAD）に貼り付ける。

この文字列が、互換性のない 2 つのサンドボックスの  
「あいだ」をつなぐ足場になっています。

そして偶然にも、そこには次のような性質が現れていました。

- 再現性
    
- 同一性の保持
    
- 宣言的操作（したことが文字列として残る）
    
- フォーマット非依存の表現
    
- 人と機械の境界設計
    
- 薄く安定した API
    

私は何かを発明したわけではありません。

ただ、すでに会社の体系に宿っていた構造が、  
Excel と AutoCAD の “あいだ” を通ることで  
別の表現で輪郭を持ち始めた──  
そんな感覚に近いものです。

---

## 7. 小さな構造は長く残る

持続可能なエンジニアリングは、  
巨大な仕組みから始まるわけではありません。

壊れずに残り続ける、  
ごく小さな構造から始まります。

フォルダひとつ、  
Excel ひとつ、  
数十のブロック。

それだけでも、  
ひとりの人間を支え、  
ワークフローを安定させ、  
見えにくかった構造を静かに形づくることがあります。

意味はツールの内側ではなく、  
その「あいだ」に宿るのだと思います。
